# 手機版新介面（原型）

> 2026-11-13 起（分支 `feat/own-engine`），新介面不再疊在 YTM 介面上：YTM 的介面不載入，資料自己呼叫 API，播放交給 YouTube 自己的播放器。下面「做法」與「分層」描述的是舊的疊加做法，新的架構見 `docs/OWN-ENGINE.md`。

狀態：`spike/mobile-ui` 分支上的驗證原型（2026-11-12）。目的是確認「YTM 當引擎、介面自己畫」這條路走得通，不是完成品。

## 做法

- music.youtube.com 照常載入，YTM 繼續負責登入、播放、待播清單、廣告處理，以及所有掛在播放器上的插件。`ytmusic-app-layout` 設成 `opacity: 0`，新介面用 Solid 畫在 shadow root（`<pear-mobile-ui>`）裡，位置在 in-app-menu 的標題列下方。YTM 的彈出視窗（登入提示、儲存至播放清單、toast）仍然顯示在新介面上方；Premium 廣告條則藏起來。
- **只有 Android 預設開啟**（`__PEAR_MOBILE__`），桌面版完全不受影響：沒開啟時 `startMobileUi()` 直接返回，不會掛上任何東西。
- 開關是設定檔的 `options.mobileUi`，在 Android 版 in-app menu 的「檢視 → Pear 行動版介面（預覽）」切換，切換後頁面會重新載入。沒設定過時是關的（Android 也是：新介面還是預覽，要自己開啟）。桌面開發時可以在 localStorage 設 `pear-mobile-ui-dev` = `on` 強制開啟（例如加在 `PEAR_INJECT_FILE` 載入的 bundle 最前面）。

## 分層

```
src/mobile-ui/
  enable.ts          開關
  engine/ytm.ts      唯一碰 YTM 內部的地方：networkManager.fetch、yt-navigate、#movie_player、queue store
  engine/history.ts  history 隔離（見下）
  model/types.ts     介面看到的資料：Item / Section / Page / Header / MenuEntry
  model/parse.ts     innertube 回應 → model（browse、search、continuation）
  ui/                App、router、頁面、清單列與卡片、播放器、bottom sheet
```

- **項目選單**直接用 innertube 回應裡每個項目附帶的 `menuRenderer`（接著播放、加入待播清單、前往專輯／藝人、儲存至播放清單、分享…），顯示成 bottom sheet。每一列、每張卡片都有看得見的 ⋮ 按鈕；長按只是開啟同一個 sheet 的捷徑。
- **帳號與 App 選單**：標題列右上角的頭像（帳號選單 `/account/account_menu` 的 `activeAccountHeaderRenderer`；YTM 隱藏導覽列裡的頭像在導覽列顯示前只是佔位圖）打開帳號 sheet：帳號名稱與代號、「YouTube Music 帳戶」（按 YTM 自己的頭像按鈕，開它的帳號選單：切換帳戶、登出），以及 Pear 的 App 選單——和 in-app-menu 標題列同一棵樹（`get-menu`），點選走 `peard:menu-event`，勾選／單選後重讀整棵樹（Rust 重建選單時會重新編號，所以子選單以標籤記路徑）。Android 上 in-app-menu 是唯一的選單入口，有了這個 sheet，它的標題列（`nav#ytmd-title-bar-main-panel`）在新介面開啟時隱藏，`--menu-bar-height` 歸零。
- **首頁**：頂端的心情／類型 chip（`sectionListRenderer.header.chipCloudRenderer`）可篩選，點選同一頁的 chip 原地換成篩選後的內容（tab 路由帶 `params`），再點一次取消。「歌曲快選」照 `numItemsPerColumn` 排成每欄 4 首、橫向翻頁。輪播區塊用清單還是卡片看 YTM 給的項目格式（`musicResponsiveListItemRenderer` → 清單），不看第一個項目的類型。
- **播放器分頁**各自記住捲動位置（共用同一個捲動容器）；待播清單切到別的分頁時保持掛載，不重建。
- **寬螢幕的 sheet** 最寬 640px 置中，兩側露出下方頁面。
- **長的播放清單**：捲到底時載入後續歌曲（清單最後一項的 `continuationItemRenderer`，回應在 `onResponseReceivedActions[].appendContinuationItemsAction`）。自己的播放清單把 `continuationCommand` 和其他指令一起包在 `commandExecutorCommand.commands` 裡。頁面底部的續載（播放清單後面的「推薦歌曲」「相關播放清單」）要等頁面上每個清單都載完才開始，和 YTM 一樣，否則推薦會插在播放清單中間，播放清單的續載點也被推離畫面。自己的播放清單的標題區包在 `musicEditablePlaylistDetailHeaderRenderer.header` 裡。
- **播放清單編輯**（例如「從播放清單中移除」，`playlistEditEndpoint`）直接呼叫 `/browse/edit_playlist`；移除畫面上清單裡的歌時，那一列在原地消失（頁面不重新載入、捲動位置不變），其他編輯才重新載入目前頁面；YTM 回應裡的訊息（例如「已在播放清單中」）會顯示在提示裡。
- **按讚與儲存至播放清單**由新介面自己處理：按讚直接呼叫 `/like/like`（`removelike`、`dislike`）；儲存至播放清單開新介面自己的 sheet，清單來自 `/playlist/get_add_to_playlist`，點一下就執行 YTM 準備好的加入動作（`playlistEditEndpoint`，`/browse/edit_playlist`），「新增播放清單」呼叫 `/playlist/create`（私人）。YouTube Music 的這個回應沒有「哪些清單已經有這首歌」的欄位（實測 10 個清單都沒有 `containsSelectedVideos`），YTM 自己的視窗也只能加入；重複加入時 YTM 回應失敗並附上「播放清單中已有這首曲目」與「仍要新增」按鈕（`DEDUPE_OPTION_SKIP` 的加入動作），新介面照樣顯示成提示加按鈕。讀不到清單時，sheet 提供改用 YTM 視窗的按鈕。未登入時這兩項是登入提示，照下一點交給 YTM。
- **執行其他選單項目**：建立一個隱藏的 YTM 選單項目元素（例如 `ytmusic-menu-service-item-renderer`），把原始資料交給它再點擊，所以行為和在 YTM 選單裡點一模一樣（加入待播清單、儲存至播放清單的彈出視窗、按讚、分享、登入提示）。直接送 `yt-navigate` 不會開任何彈出視窗，送 `yt-service-request` 加入待播清單時只會跳出提示。`browseEndpoint` 由新介面自己開頁面；列表與標題區的播放按鈕（`watchEndpoint`、`watchPlaylistEndpoint`）送 `yt-navigate`。
- **播放器**：寬螢幕（橫向、寬度 ≥ 840px）右側固定顯示待播清單／歌詞／相關內容分頁；窄螢幕的分頁列露在畫面底部，往下滑或點分頁會捲到下方。歌詞與相關內容來自 `/next` 回應裡的分頁（`MPLY…`、`MPTR…` 的 browseId）。
- **廣告**：播放器帶 `ad-showing` 時，迷你播放器與播放器變成黃色，封面位置顯示廣告影片，歌名換成廣告標題（播放器隱藏的標題列 `.ytp-title-link`，去掉「第 1 則…」與倒數時間）並加上「廣告」標記，藝人換成贊助商（`.ytp-ad-button-text`，解開百分比編碼）。
  - **影片**：廣告期間把 YTM 的 `<video>` 搬進新介面（`showVideo`）：在 YTM 播放器裡留一個佔位元素，把 `<video>` 設成 host 的子元素並指定 `slot`（播放器開著時是播放器的影片區，否則是迷你播放器的封面），廣告結束時放回佔位元素的位置。`<video>` 仍在 document 樹裡，`document.querySelector('video')` 與插件都找得到；YTM 會一直改寫它的 inline 大小與位置，用 document 樣式表的 `!important` 規則蓋過。不用 canvas：Android 的 GeckoView 無法把硬體解碼的畫格畫到 canvas（全黑）。影片是新介面的一般元素，所以「略過廣告」疊在影片右下角，sheet 也正常蓋在它上面。
  - **略過**：YouTube 的略過鈕不接受程式觸發的點擊。「略過廣告」是頁面裡（host 的子元素）指向略過鈕的 `<label>`，透過 slot 顯示在新介面裡；使用者點 label 時，瀏覽器把點擊轉交給略過鈕，而且是可信任的點擊（`isTrusted: true`），所以是真正的略過，和在 YTM 裡按一樣（會結束整段廣告）。label 只能找到同一棵樹裡的元素，所以不能放在 shadow root 裡。播放器裡疊在影片右下角（半透明黑底），迷你播放器裡取代右側的 ⋮。
  - **外框**：影片照廣告本身的比例顯示（不一定是 16:9，讀 `videoWidth / videoHeight`），圓角用 `clip-path` 裁切（`<video>` 是 host 的子元素，外層的 `overflow: hidden` 管不到它）。
- **跟著 YTM 的播放器與 `<video>`**：引擎綁定 `#movie_player`（播放器事件、廣告狀態）與 `<video>`（播放狀態、時間）時，YTM 換掉其中一個就重新綁定（document 的 childList 變化後檢查）。冷啟動時曾看到引擎綁在 YTM 已經不用的元素上，播放鍵與廣告狀態都不跟著變。
- **轉給 YTM 的點擊**（播放列按鈕、選單項目、登入連結）一律經過 `press()`：觸控之後 2.5 秒內，YTM 的 Polymer 手勢程式會把路徑上沒有剛才觸控元素的點擊當成殘影點擊（ghost click）取消，新介面轉給 YTM 的點擊全都符合這個條件，所以在觸控螢幕上全部失效（滑鼠與程式觸發的點擊不受影響，桌面與模擬器測不出來）。它會放行 `sourceCapabilities.firesTouchEvents` 為 false 的事件；Chrome 會設這個屬性，Gecko 沒有，所以點擊事件自己帶上。
- **播放器按鈕**：上一首／下一首、隨機播放、重複播放、喜歡／不喜歡都按 YTM 播放列上的按鈕（點按鈕內部的原生 `<button>`；找不到上一首／下一首時改用播放器 API），狀態讀播放列的 `repeat-mode` 與 `like-status`。迷你播放器分成三段：左邊是縮圖與歌曲資訊，中間是上一首／播放暫停／下一首（廣告時上一首仍顯示但停用），右邊是操作選單（廣告時換成「略過廣告」）。
- **待播清單**在換歌時捲到目前播放的歌曲（只在換歌時，待播資料的其他更新不捲動）；YTM 的待播項目沒變的，沿用原本的列（整個重建會讓捲動位置跳回最上面）；捲到底時用 YTM 待播服務上的續載標記（`#queue` 的 `queue.continuation`）呼叫 `/next`，只把歌曲項目（回應裡還有說明訊息與自動合輯預覽，YTM 的待播程式遇到會拋出錯誤）用 `ADD_ITEMS` 加進 YTM 的待播資料，再把續載標記換成下一頁（避免 YTM 重複載入）。YTM 自己只在它（隱藏的）待播列表捲到底時載入，新介面下永遠不會發生。加入／移除待播時顯示提示（YTM 不會說）。
- **待播清單的歌曲**也有 ⋮ 與長按選單（YTM 待播項目自帶的 `menuRenderer`，包含「從待播清單中移除」）。左側的拖曳控制點可以調整順序：放開時呼叫 YTM 待播列表自己的 `onDrop`（傳入一個假的拖曳元素：`data` 是那首歌的 YTM 項目，位置是目標的索引），它會更新待播資料，也同步伺服器端的待播與投放；萬一 YTM 改了這段程式而沒有移動，改送 `MOVE_ITEM`。拖到清單上下緣時會自動捲動。
- **操作選單**：每一項加上圖示（依 YTM 的 `iconType` 對應）；「接著播放」「儲存至播放清單」「分享」照 YTM App 的樣子放在最上面，成為三個大按鈕。
- **帳號 sheet**：讀 `/account/account_menu`，把 YTM 的帳號選單畫在新介面裡（不再另外打開 YTM 的帳號選單）。最上面是頭像、名稱與代號，點了開「你的頻道」；「你的頻道」與「觀看記錄」（`browseEndpoint`）由新介面開頁面，其他項目（切換帳戶、登出、上傳歌曲、設定、條款、說明、提供意見）建立隱藏的 `ytd-compact-link-renderer` 交給 YTM 執行，和在 YTM 選單裡點一樣。「訂閱 Music Premium」略過（新介面無法顯示那個頁面）。下面接 Pear 設定。
- **按鍵**：新介面文字欄位裡的按鍵在 window 的 capture 階段就停止傳遞，YTM 的快捷鍵（空白鍵暫停等）收不到；文字輸入是按鍵的預設動作，不受影響。
- **history 隔離**：YTM 每次導覽（例如播放時跳到 `/watch`）都會 push 一筆紀錄，也會監聽 popstate。新介面開啟時，YTM 的 `pushState` 會改成 `replaceState`（網址仍跟著播放內容走），popstate 則在 capture 階段攔下、不讓 YTM 收到，改成讓新介面退一層（頁面、播放器、待播清單、選單 sheet）。每開一層就 push 一筆，所以 Android 返回鍵（`GeckoSession.goBack`）和介面上的返回／關閉按鈕都走同一條路。這必須在 YTM 的腳本執行前安裝，注入的 bundle 正是在 document start 執行。

## 原型：把 YTM 的 `<video>` 搬進新介面（平板，2026-11-13）

想法（使用者提出）：與其把 YTM 的版面設回可見、讓 `<video>` 疊在新介面上，不如把 `<video>` 本身搬進新介面。以遠端除錯在平板（GeckoView、登入狀態）上手動操作：在 YTM 的容器留一個空的佔位元素，把 `<video>` 設成 host 的子元素（`slot="…"`，留在 document 樹裡，`document.querySelector('video')` 與插件都還找得到），由新介面裡的 `<slot>` 顯示。

| 檢查 | 結果 |
|---|---|
| 搬移時播放是否中斷 | 不中斷（25.1 → 29.3 秒持續前進），搬來搬去都沒有任何 `pause`／`play`／`waiting` 等事件 |
| 換歌時 YTM 會不會搬回去 | 不會：換到下一首（有畫面的 MV）後仍在新介面裡 |
| 廣告 | 廣告和正片共用同一個 `<video>`，廣告直接在新介面裡播放；廣告切換時也沒被搬回去 |
| Gecko 解碼與顯示 | 可見時正常解碼（640 寬、數百格），畫面正常顯示（不需要 canvas，沒有全黑問題） |
| YTM 改寫樣式 | YTM 會持續改寫 `<video>` 的 inline 寬高與位置，正式做法要用樣式表的 `!important` 規則蓋過 |

結論：可行，已取代原本的疊加做法（見上方「廣告」）。好處：影片是新介面的一般元素，略過按鈕可以疊在影片右下角，sheet 正常蓋在它上面，不用再讓 YTM 版面可見，也沒有位置偏移；同一個機制也能做 MV 的影片模式。
